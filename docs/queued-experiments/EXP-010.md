# EXP-010: Scrape quality diagnostics

**Status:** Ready to run
**Effort:** Small
**Priority:** Medium
**Agent:** awards-verifier

---

## Task

Compute scrape quality metrics for each of the 321 candidates and identify projects where thin or failed scrapes may have suppressed scores.

## Inputs

- `cache/sites.sqlite` — cached page fetches (HTML body, fetch status, error fields)
- `data/enriched/` — dossier files (to check if Jina fallback was used and to cross-reference scores)
- `results.json` — current rankings

## Method

For each candidate URL:

1. Query `cache/sites.sqlite` for:
   - Fetch status (success/failed/error)
   - Body character count (if fetched)
   - Error type (if failed)

2. Classify each project into a scrape quality tier:
   - **Rich**: body > 3000 chars, no error
   - **Thin**: body exists but < 500 chars
   - **Failed**: error or no body
   - **Jina fallback**: check dossier for evidence of fallback fetch

3. Join to results.json. For each tier, compute:
   - Mean score and score distribution
   - Presence in v6 shortlist (183 projects)
   - Rank in results.json

4. Identify specific projects where:
   - Scrape quality is "failed" or "thin" but the project appears to be substantive (based on enriched dossier fields)
   - These are candidates for targeted re-fetch or manual content addition

## Output

- `experiments/EXP-010/scrape-quality-report.md` — summary statistics and tier distributions
- `experiments/EXP-010/re-fetch-targets.md` — list of projects worth targeted re-fetching
- Key finding: is there a systematic bias where thin-scrape projects score lower?

## Constraints

- Do NOT re-fetch any pages as part of this experiment — analysis only
- If re-fetching is warranted, that is a separate task

## Definition of done

Report produced with tier statistics, bias analysis, and re-fetch target list.
