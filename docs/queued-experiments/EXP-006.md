# EXP-006: Intake validation ruleset for non-project URLs

**Status:** Ready to run
**Effort:** Small
**Priority:** Medium
**Agent:** awards-verifier

---

## Task

Produce a flagged list of candidate URLs that are likely not standalone projects (papers, templates, blog posts, GitHub READMEs, etc.) so they can be reviewed for exclusion before any future enrichment or scoring runs.

## Inputs

- `candidates.csv` — full list of 321 candidate URLs
- `data/enriched/` — dossier files for context on `project_type` and other fields

## Method

Apply the following checks to each candidate:

1. **URL pattern checks:**
   - Does the URL point to a PDF? (ends in `.pdf` or contains `/pdf/`)
   - Does the URL point to a GitHub repository README? (github.com/*/blob/main/README*)
   - Does the URL point to a blog post? (contains `/blog/`, `/post/`, `/article/`, `/medium.com/`)
   - Does the URL point to a specific page rather than a project homepage? (URL has 3+ path segments suggesting it's a sub-page)

2. **Dossier field checks (where enriched dossier exists):**
   - Is `project_type` set to "paper", "template", "post", "guide", or "framework document"?
   - Is `org_type` set to a value suggesting this is a document rather than a project?

3. **Fetch failure check:**
   - Is the URL flagged as failed in `cache/sites.sqlite`?

Produce a prioritised list:
- **High confidence non-project**: matches URL pattern + dossier field evidence
- **Possible non-project**: matches one signal only
- **Review flagged**: something suspicious but not conclusive

## Output

- `experiments/EXP-006/flagged-candidates.md` — table of flagged URLs with signals and confidence level
- Summary count: how many high-confidence, possible, and review-flagged candidates

## Constraints

- Do NOT remove any candidates from `candidates.csv` — this is a flagging and review task only
- All removals require human review and approval

## Definition of done

Flagged list produced, counts summarised, ready for human review.
