# EXP-002: Calibration-aware shortlist normalisation

**Status:** Ready to run
**Effort:** Small
**Priority:** High
**Agent:** awards-builder

---

## Task

Normalise each model's bucket assignment rates before applying the shortlist rule, so Claude's structural conservatism doesn't distort the shortlist composition.

## Inputs

- `iterations/v6/` — all three model assessments:
  - `assessments-grok.json` (120 greens / 321 projects)
  - `assessments-all-claude.json` (3 greens / 321 projects)
  - `assessments-all-kimi.json` (33 greens / 321 projects)

## Method

1. For each model, compute:
   - Green rate (greens / 321)
   - Green+Yellow rate ((greens+yellows) / 321)

2. Define a normalisation target (e.g. 30% green+yellow rate for all models)

3. For each model, find the threshold score/bucket count that produces the target rate. Re-classify projects above the threshold as "normalised green" for shortlisting purposes.

4. Apply the 2-of-3 shortlist rule on normalised buckets. Compare the resulting shortlist to the original 183-project v6 shortlist:
   - How many projects enter that weren't in the original?
   - How many projects exit?
   - What types of projects are most affected?

## Output

- `experiments/EXP-002/normalised-shortlist.json` — the new shortlist
- `experiments/EXP-002/analysis.md` — comparison table and interpretation
- Recommendation: should normalisation be adopted in future iterations?

## Constraints

- Do NOT run new model evaluations — work only from existing assessment files
- Clearly document the normalisation method chosen and why

## Definition of done

Normalised shortlist produced, comparison analysis written.
